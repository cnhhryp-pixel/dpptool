Before importing

  • One stable product ID per row
  • Consistent units and controlled values
  • Supplier IDs instead of free-text names where possible
  • Consistent document references

What the starter CSV is designed for

The template is intentionally simple. It helps teams move from unstructured files and spreadsheets toward a consistent product-data table that can later be mapped into a DPP platform, JSON model or API.

Recommended preparation rules

RuleWhy it matters
One stable product ID per rowPrevents duplicate records when product names change.
Separate supplier IDs from supplier namesMakes upstream evidence easier to join across systems.
Keep document references consistentLets declarations and test reports stay linked to the correct product version.
Use controlled valuesReduces spelling and unit inconsistencies before import.
Preserve raw source evidenceStructured fields should not replace the original supporting document.

CSV is a staging format, not the final passport

A real DPP implementation may require APIs, structured JSON, Registry interactions, access control and lifecycle updates. CSV is most useful as a portable preparation and migration layer.
